# Итерация 0: Требования к UI и API-контракты для frontend

## Цель

Зафиксировать функциональные требования к экранам web-клиента системы мониторинга оборудования и спроектировать API-контракты.

## Технологический стек

- Next.js (App Router) + React + TypeScript
- shadcn/ui + Tailwind CSS
- pnpm

---

## Экраны интерфейса

### Экран 1 — Панель обзора площадки (`/dashboard`)

**Назначение:** любой посетитель портала сразу получает ответ — что происходит, всё ли работает.

**Виджеты:**

1. **Индекс состояния площадки** — единый агрегированный badge (green/yellow/red), рассчитывается по worst-status-wins по всему оборудованию
2. **Сводка по статусам** — количество оборудования в каждом статусе (normal/warning/critical/unknown)
3. **График состояния за 14 дней** — ежедневная разбивка: сколько единиц оборудования в каждом статусе по дням (stacked bar или area chart)
4. **Топ проблемного оборудования** — top-N единиц с наихудшим/самым свежим critical/warning статусом
5. **Лента изменений состояния** — хронологический список недавних переходов статусов оборудования (с пагинацией)
6. **Лента действий** — недавние ручные фиксации состояния со ссылками на карточку оборудования (с пагинацией, кликабельно)

---

### Экран 2 — Панель обзора оборудования (`/dashboard/equipment/{equipment_id}`)

**Виджеты:**

1. **Индекс состояния оборудования** — badge (green/yellow/red) на основе `current_status`
2. **Переключатель данных** — переключаемое представление: таблица общих данных по машине vs. ключевой индивидуальный параметр
3. **Прогресс-бар ТО** — процент завершения до следующего планового обслуживания
4. **Топ-3 критических узла** — sensor groups с наихудшим статусом, отсортированные по severity
5. **История оборудования** — лента state records + snapshots по данному оборудованию (с пагинацией)

---

### Экран 3 — Панель обзора узла (`/dashboard/equipment/{equipment_id}/nodes/{sensor_group_id}`)

**Виджеты:**

1. **Индекс состояния узла** — badge (green/yellow/red)
2. **Фото узла** — изображение (nullable `image_url` на `sensor_groups`)
3. **Мониторируемые характеристики** — список датчиков с последними значениями
4. **AI-диагностика** — интерпретация текущего состояния от LLM через `POST /api/v1/assistant/messages` с `equipment_context`
5. **Рекомендации** — при yellow/red: объяснение причин и корректирующие действия для предотвращения остановки производства (часть ответа AI-диагностики)

---

### Глобальный AI-чат (floating, все экраны)

- Плавающая кнопка на каждой странице, раскрывается в панель чата
- Использует `POST /api/v1/assistant/messages`
- Хранит `conversation_id` в рамках сессии
- Автоматически передаёт `equipment_id` / `sensor_group_id` из контекста текущей страницы

## Правило агрегации статусов

- Принцип: **worst-status-wins** снизу вверх
- Направление: узел (sensor_group) → оборудование (equipment) → площадка (plant)
- Маппинг:
  - `normal` = зеленый
  - `warning` = жёлтый
  - `critical` = красный
  - `unknown` = серый
- Глубина иерархии настраивается: от плоской (площадка → оборудование → узлы) до глубокой (площадка → цех → участок → оборудование → узлы)

## Стиль UI

- **Тема:** переключение светлая/тёмная, тёмная по умолчанию
- **Стилистика:** dev-style, чистый монохром с акцентными цветами для статусных badge'ей
- **Референс:** https://www.tbench.ai/
- **Цвета статусов:**
  - green: `#22c55e`
  - yellow: `#eab308`
  - red: `#ef4444`
  - gray: `#6b7280`

## Временная схема входа

- Форма входа: поле ввода Telegram username
- Backend: по username resolve/create `system_actor` и возвращает сессию
- Без паролей, без OAuth
- **План миграции:** в будущем переход на вход по логину и паролю

## Новые API-контракты

Подробное описание всех новых endpoint'ов зафиксировано в:
- `backend/docs/api-contracts.md`
- `backend/docs/openapi.yaml`

**Сводка новых endpoint'ов:**

| Группа | Method | Path | Назначение |
|--------|--------|------|------------|
| Auth | POST | /api/v1/auth/login | Вход по Telegram username |
| Auth | GET | /api/v1/auth/me | Текущий пользователь |
| Dashboard | GET | /api/v1/dashboard/plant | Обзор площадки (статус, сводка, график, top) |
| Dashboard | GET | /api/v1/dashboard/state-feed | Лента изменений состояния |
| Dashboard | GET | /api/v1/dashboard/action-feed | Лента действий |
| Equipment | GET | /api/v1/equipment | Список оборудования |
| Equipment | GET | /api/v1/equipment/{id} | Детали оборудования |
| Equipment | GET | /api/v1/equipment/{id}/history | История состояния |
| Nodes | GET | /api/v1/sensor-groups/{id} | Детали узла |
| Locations | GET | /api/v1/locations/tree | Дерево локаций |
| Admin | GET | /api/v1/admin/dashboard | KPI и активность |
| Admin | GET | /api/v1/admin/clients | Таблица клиентов |
| Admin | GET | /api/v1/admin/events | Лента событий |
