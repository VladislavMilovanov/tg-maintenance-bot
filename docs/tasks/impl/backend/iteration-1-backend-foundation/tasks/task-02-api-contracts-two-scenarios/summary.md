# Задача 02: API-контракты двух сценариев

## Итог

Задача завершена в рамках итерации 1.

## Что сделано

- добавлен основной OpenAPI-first артефакт `backend/docs/openapi.yaml`;
- добавлен companion-doc `backend/docs/api-contracts.md` с кратким описанием сценариев и ограничений MVP;
- зафиксированы контракты `POST /api/v1/assistant/messages` и `POST /api/v1/equipment-state-records`;
- введён единый error-shape для типовых ошибок API;
- синхронизированы `docs/data-model.md` и `docs/integrations.md` под принятые DTO и потоки;
- обновлён `docs/tasks/tasklist-backend.md` ссылками на фактические артефакты задачи.

## Принятые решения

- OpenAPI является источником истины для контрактов и кодов ошибок.
- Assistant flow принимает клиентский контекст и возвращает `fallback_used` в `meta`, если backend не смог получить полноценную интерпретацию.
- Фиксация состояния на этапе MVP описана минимально: оборудование, статус, комментарий, время наблюдения, канал и автор.
- Прямой вызов LLM из клиентов не рассматривается как целевая архитектура.
