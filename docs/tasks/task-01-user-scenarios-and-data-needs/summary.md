# Задача 01: Пользовательские сценарии и требования к данным

## Итог

Задача завершена.

## Что сделано

- создан ключевой сценарный артефакт `docs/spec/user-scenarios.md`;
- зафиксированы роли `клиент/инженер` и `админ`, а также 6 базовых пользовательских потоков;
- выделены обязательные представления данных и минимальные доменные сущности;
- синхронизированы `docs/vision.md`, `docs/data-model.md` и `backend/docs/api-contracts.md`;
- в документации разведены `current state` и `state record`, а также отмечены `owner`, `data source` и review-поля как обязательные data requirements.

## Принятые решения

- сценарии живут в отдельном `docs/spec/user-scenarios.md`, а не размазываются по нескольким документам;
- продуктовая операционная роль фиксируется как единый `клиент/инженер`;
- текущие API DTO не расширяются новыми workflow-полями раньше data layer;
- review и source semantics считаются частью доменной модели, даже если ещё не выражены в MVP API.
