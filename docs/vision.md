# Техническое видение проекта

Документ развивает идею из [idea.md](idea.md) и задаёт техническое направление MVP.

---

## Технологии

- **Python 3.12+** — основной язык
- **aiogram 3.x** — фреймворк для Telegram Bot API (polling, без webhook)
- **httpx** — HTTP-клиент для API (OpenRouter)
- **uv** — менеджер зависимостей и пакетов
- **make** — автоматизация команд

---

## Зависимости

**Основные:**
- `aiogram` — Telegram-бот
- `openai` — клиент OpenAI-совместимых API (для OpenRouter)

**Вспомогательные:**
- `pydantic` — валидация и парсинг конфигурации
- `python-dotenv` — загрузка переменных окружения

При необходимости: `httpx` (если `openai` недостаточно).

---

## Виртуальное окружение

Используется `venv`, управление через `uv`:
- `uv venv` — создание окружения
- `uv pip install -e .` — установка проекта в режиме разработки
- активация: `source .venv/bin/activate` (Linux/macOS)

---

## Сборка

**Makefile** с целевыми командами:
- `install` — создание venv и установка зависимостей
- `run` — запуск бота
- `lint` — проверка линтером (ruff)
- `format` — форматирование (ruff format)

Зависимости описаны в `pyproject.toml`, скрипты запуска — там же.

---

## Принципы разработки

- **KISS** — только необходимое для MVP, без лишних абстракций
- **Один класс — один файл** — при использовании ООП
- **Минимум слоёв** — handlers → LLM-сервис → внешние API, без лишних прослоек
- **Связь с idea.md** — каждая фича должна явно опираться на задачи из идеи

## Архитектура

**Слои:**
1. **Handlers** — приём сообщений от пользователя, передача в сервис
2. **LLM-сервис** — формирование промпта, вызов OpenRouter, разбор ответа
3. **Источник данных** — в MVP простой источник (файл, мок). Детали — в «Модель данных»

Поток: Telegram → aiogram → handler → LLM → OpenRouter → ответ → пользователю.

---

## Модель данных / состояние

**В MVP:**
- Состояние оборудования — структурированные данные (JSON/словарь): id машины, метрики (вибрация, температура и т.п.), статус
- Источник: локальный файл или переменные окружения. API мониторинга — позже
- В памяти бота: только текущий диалог (при необходимости), без отдельной БД

---

## Работа с LLM

- **Провайдер:** OpenRouter (OpenAI-совместимый API)
- **Клиент:** `openai.OpenAI(base_url="https://openrouter.ai/api/v1", api_key=...)`
- **Промпт:** системный промпт с ролью «помощник по состоянию оборудования», простой язык, без технических терминов
- **Контекст:** в запрос передаются вопрос пользователя + данные о выбранной машине (если указана)

---

## Сценарии работы пользователя

1. Пользователь пишет боту (например: «Что с машиной X?»)
2. Бот определяет, о какой машине речь (из контекста или по умолчанию)
3. Бот загружает данные по машине из источника
4. Бот формирует промпт и запрашивает LLM
5. Бот отправляет ответ пользователю простым языком

Дополнительно: если машина не указана — бот просит уточнить или показывает список.

## Конфигурация и секреты

- **Файл:** `.env` (в `.gitignore`)
- **Переменные:**
  - `TELEGRAM_BOT_TOKEN`
  - `OPENROUTER_API_KEY`
  - путь к данным оборудования (опционально, с дефолтом)
- **Загрузка:** `python-dotenv`, валидация через `pydantic.BaseSettings` (или `pydantic-settings`)

---

## Логирование

- `logging` из stdlib
- Уровень: INFO по умолчанию, DEBUG через переменную окружения
- Логировать: входящие запросы, вызовы LLM, ошибки (без токенов и ключей)

## Сборка и запуск

```bash
make install   # venv + зависимости
make run       # python -m maintenance_bot
```

Запуск через `uv run` или активированное venv.
